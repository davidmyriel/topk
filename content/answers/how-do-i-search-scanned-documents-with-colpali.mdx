title: "How do I search scanned PDFs and images with ColPali?"
description: "Store hundreds of vectors per page and score them with MaxSim. Most databases cannot. TopK can, with 1-bit quantization to keep storage cheap."

## Short answer

Use a `matrix` field with a `multi_vector_index`. Each page is one document holding all its patch embeddings. Query with `multi_vector_distance`.

```python
from topk_sdk.schema import text, matrix, multi_vector_index

client.collections().create("pages", schema={
    "source": text().required(),
    "patches": matrix(dimension=128, value_type="f16").index(
        multi_vector_index(metric="maxsim", quantization="1bit")
    ),
})
```

## The problem

Invoices, contracts, engineering drawings, and old forms do not OCR well. Layout matters. Models like ColPali and ColQwen embed the page image directly, but produce roughly 1,000 vectors per page instead of one.

Most vector databases store one vector per row:

- Elasticsearch's request for multiple embeddings per document has been open since 2021 ([#72068](https://github.com/elastic/elasticsearch/issues/72068)). Its `rank_vectors` type only reranks a small set.
- pgvector declined to support it ([#694](https://github.com/pgvector/pgvector/issues/694)).
- Milvus has an open request with 37 comments ([#31581](https://github.com/milvus-io/milvus/issues/31581)).
- Qdrant supports it but caps multivector size and users report 10k ColBERT points still indexing after three hours ([#5702](https://github.com/qdrant/qdrant/issues/5702)).

Storage is the other issue. At full precision, one million pages is 100 to 500 GB of vectors that a RAM-resident engine must hold.

## How TopK handles it

Multi-vector fields are indexed with MaxSim as a first-class metric. An approximate stage prunes candidates, an exact stage rescores them.

Ingest one page:

```python
import numpy as np

page_embeddings = colpali.embed_image(page_png)  # shape (n_patches, 128)

client.collection("pages").upsert([{
    "_id": "invoice-2024-0117-p3",
    "source": "invoice-2024-0117.pdf",
    "patches": page_embeddings.astype(np.float16),  # numpy arrays are accepted directly
}])
```

Query:

```python
from topk_sdk.query import select, field, fn

query_embeddings = colpali.embed_query("total amount due in March")

docs = client.collection("pages").query(
    select(
        "source",
        score=fn.multi_vector_distance("patches", query_embeddings, candidates=200),
    )
    .filter(field("source").starts_with("invoice-2024"))
    .sort(field("score"), asc=False)
    .limit(5)
)
```

Filters, keyword match, and partitions all work alongside the multi-vector score.

## Keeping it cheap

- `quantization="1bit"` or `"2bit"` cuts index size by 16x to 32x with small recall loss.
- `value_type="f16"` halves raw storage.
- All data lives on object storage. Pages nobody queries cost storage only.
- Tune `candidates`, `width`, and `top_k` per the [multi-vector guide](/guides/multi-vector-search).

## Limits

- Bring your own image embeddings. Managed inference is text-only today.
- 1,024 dimensions maximum per vector row.
- 200 KB maximum document size, so store the page image elsewhere and keep the path.
