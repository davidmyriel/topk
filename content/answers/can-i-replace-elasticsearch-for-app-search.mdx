## Short answer

TopK exposes an Elasticsearch-compatible API. Official `elasticsearch-py`, `-js`, `-rs`, and `-java` clients connect. Supported:

- `PUT /{index}` with `mappings.properties` for `text`, `keyword`, `integer`, `float`, `boolean`, `object`, `dense_vector` (float, byte, bit), `rank_vectors` for multi-vector, `semantic_text`
- `_bulk`, `_doc`, `_mget`, `_msearch`, `_count`, `_mapping`, `_field_caps`, `_refresh`
- Query DSL: `match`, `multi_match`, `term`, `terms`, `ids`, `prefix`, `regexp`, `range`, `exists`, `bool`, plus a `semantic` clause
- `knn` with one or more clauses, filters, and matrix query vectors for ColBERT-style search
- `rank.rrf` hybrid fusion, free
- `terms` aggregation with `sum`, `avg`, `min`, `max`, `value_count` sub-aggregations

## The problem

- RRF hybrid search in Elasticsearch requires a Platinum or Enterprise license. Free users get `license is non-compliant` ([langchain-elastic #38](https://github.com/langchain-ai/langchain-elastic/issues/38)).
- Semantic search needs dedicated ML nodes, 4 GB minimum, and ELSER is a paid feature.
- Vector fields must fit in page cache ([#93670](https://github.com/elastic/elasticsearch/issues/93670)). OpenSearch's native memory circuit breaker OOM-kills nodes ([k-NN #1301](https://github.com/opensearch-project/k-NN/issues/1301)).
- One index per tenant hits the 1,000 shards-per-node limit ([#20705](https://github.com/elastic/elasticsearch/issues/20705)).
- Substring and leading-wildcard queries are slow enough that Elastic added a whole `wildcard` field type ([#48852](https://github.com/elastic/elasticsearch/issues/48852)).

## Example

```python
from elasticsearch import Elasticsearch

es = Elasticsearch("https://<region>.es.topk.io", api_key="<api-key>")

es.indices.create(index="products", mappings={"properties": {
    "name": {"type": "text"},
    "brand": {"type": "keyword"},
    "description": {"type": "semantic_text"},
    "image_vec": {"type": "dense_vector", "dims": 512, "similarity": "cosine"},
}})

es.search(index="products", body={
    "query": {"bool": {
        "must": [{"match": {"name": "headphones"}}],
        "filter": [{"term": {"brand": "sony"}}],
    }},
    "knn": {"field": "image_vec", "query_vector": [...], "k": 20, "num_candidates": 100},
    "rank": {"rrf": {"rank_constant": 60, "rank_window_size": 100}},
    "aggs": {"brands": {"terms": {"field": "brand", "size": 10}}},
    "size": 10,
})
```

## What does not work

- No Kibana or OpenSearch Dashboards. System indices with a leading dot are rejected.
- No ILM, data streams, index templates, aliases, `_reindex`, `_update_by_query`, `_delete_by_query`.
- No `date_histogram`, `cardinality`, `percentiles`, `composite`, or nested `terms` aggregations.
- No `search_after`, `scroll`, or point-in-time. `from + size` is capped at 10,000.
- No `wildcard`, `query_string`, `fuzzy`, `match_phrase`, `nested`, `function_score`, or `script_score`.
- No auto-generated document IDs. Every bulk action needs `_id`. No `create` action.
- No `date` field type. Store epoch milliseconds as `integer`.
- Partitions are not reachable through this API.

Use it for application search: catalogs, documents, help centers, semantic and hybrid retrieval. Do not use it for logs, metrics, or dashboards.
