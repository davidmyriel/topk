---
title: "Why does my filtered vector search return fewer results than I asked for?"
description: "You asked for 10 nearest neighbors with a WHERE clause and got 3. Here is why it happens in HNSW-based databases and how TopK guarantees the filter is honored."
---

## Short answer

Most vector databases find the nearest neighbors first and apply your filter afterwards. If the filter removes most of them, you get fewer than you asked for, or nothing.

TopK applies the filter first, then ranks. If 10 matching documents exist, you get 10.

## The problem

You run something like this:

```sql
SELECT id FROM docs
WHERE tenant_id = 42
ORDER BY embedding <=> $query
LIMIT 10;
```

The index returns its 10 closest vectors across the whole table, then the database drops any that are not tenant 42. Three survive. You asked for 10.

This is the most-discussed issue in pgvector ([#259](https://github.com/pgvector/pgvector/issues/259), 87 comments). The same failure shows up as "returns less than topk" in Milvus (~47 issues), and as filter-recall requests in Elasticsearch ([#106994](https://github.com/elastic/elasticsearch/issues/106994)) and Weaviate ([#2393](https://github.com/weaviate/weaviate/issues/2393)).

Common workarounds all have costs:

- Raise `ef_search` so the index over-fetches. Slower, still not guaranteed.
- One partial index per tenant. Does not scale past a few hundred.
- Iterative scans (pgvector 0.8). One reporter saw latency go from 229 ms to 3.2 s.

## How TopK handles it

Filters run before top-k. From the [concepts](/concepts#filtering) page:

> Filters are always applied before sorting and aggregation (top-k) to guarantee that the final results contain every document matching the filter, even if there is just one. We also guarantee that recall stays the same (or improves) when using highly selective filters.

The filter and the similarity score are part of one query plan, so there is no second pass to drop rows.

```python
from topk_sdk.query import select, field, fn

docs = client.collection("docs").query(
    select(
        "title",
        similarity=fn.vector_distance("embedding", query_vector),
    )
    .filter(field("tenant_id") == 42)
    .filter(field("published_year") > 2020)
    .sort(field("similarity"), asc=False)
    .limit(10)
)
```

Filters can be any expression: comparisons, `AND`/`OR`, `in`, regex, keyword match, or a computed score.

For per-tenant data, use a [partition](/concepts#multi-tenancy) instead of a filter. The engine then scans only that tenant's data.

```python
client.collection("docs", "tenant-42").query(
    select("title", similarity=fn.vector_distance("embedding", query_vector))
    .sort(field("similarity"), asc=False)
    .limit(10)
)
```

## What to expect

- Dense vector search is approximate with 95%+ recall. Sparse vector search is exact.
- Highly selective filters do not lower recall.
- No index tuning parameters to set.
