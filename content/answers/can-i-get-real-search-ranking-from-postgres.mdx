## Short answer

Connect with `psql`, `psycopg2`, `node-postgres`, or JDBC. Create a table with inline indexes. Query with `bm25_score()`, `LIKE`, regex, and `vector_distance()` in plain SQL.

```bash
psql "host=<region>.sql.topk.io port=5432 user=topk password=<api-key> dbname=topk"
```

```sql
CREATE TABLE tickets (
    subject TEXT NOT NULL INDEX keyword_index(),
    body    TEXT          INDEX ngram_index(),
    summary TEXT          INDEX semantic_index()
);

SELECT _id, subject, bm25_score() AS score
FROM tickets
WHERE match('refund delayed', subject)
ORDER BY score DESC
LIMIT 10;

SELECT _id, subject
FROM tickets
WHERE body LIKE '%ERR-4031%'
LIMIT 10;
```

## The problem

- Postgres `ts_rank` has no inverse document frequency, no term saturation, no length normalization. Ranking is poor. Supabase users asked for a BM25 extension ([discussion #18061](https://github.com/orgs/supabase/discussions/18061), 59 upvotes). ParadeDB has around 9,000 stars for solving exactly this.
- `LIKE '%term%'` with `pg_trgm` produced a 58 GB index on 83 million rows and 42 second queries (pgsql-general list). Short or common patterns fall back to sequential scans.
- The usual fix is running Elasticsearch next to Postgres and syncing with Debezium, Logstash, or triggers. ZomboDB (4,700 stars) and pgsync (1,400 stars) exist because that sync is painful.

## How TopK handles it

One engine, Postgres protocol on the front:

- `keyword_index()` gives BM25 with tunable `b` and `k1`.
- `ngram_index()` accelerates `LIKE '%x%'`, `contains()`, and `~` regex.
- `semantic_index()` embeds text server-side. `semantic_similarity(field, 'query text')` needs no embedding call in your app.
- `vector_index()` on `f32_vector(n)` columns for your own embeddings.
- `GROUP BY` with `HAVING`, `EXTRACT`, `CASE WHEN`, `BETWEEN`, `IN`, prepared statements with `$1`.

Hybrid ranking in SQL:

```sql
SELECT _id, subject,
       semantic_similarity(summary, 'customer wants money back') AS sem,
       bm25_score() AS kw
FROM tickets
WHERE match('refund', subject) AND created_ts > TIMESTAMP '2026-01-01'
ORDER BY sem * 0.7 + kw * 0.3 DESC
LIMIT 10;
```

## What does not work

Read this before migrating.

- No `JOIN`, subqueries, CTEs, or `UNION`. Denormalize filter columns into the search table.
- No `SELECT *`. List columns.
- `BEGIN`/`COMMIT` are accepted and ignored. There are no transactions.
- `ORDER BY` requires `LIMIT`. Single `ORDER BY` key.
- No `ALTER TABLE`, `CREATE INDEX`, `RETURNING`, `ON CONFLICT`, row-level security, or stored functions.
- Metabase, dbt, and ORM migrations expect the things above and will not work. Raw-SQL clients and Grafana panels do.

TopK is a search table next to your Postgres, not a Postgres replacement.
