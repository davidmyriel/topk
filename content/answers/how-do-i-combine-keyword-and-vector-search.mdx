---
title: "How do I combine keyword search and vector search in one query?"
description: "Hybrid search without running two queries and merging them in your app. One index, one scoring expression, one result list."
---

## Short answer

Put a BM25 score and a semantic score in the same `select`, then sort by any formula of the two.

```python
from topk_sdk.query import select, field, fn, match

docs = client.collection("products").query(
    select(
        "name",
        keyword=fn.bm25_score(),
        semantic=fn.semantic_similarity("description", "blue phone protector"),
    )
    .filter(match("iphone 15"))
    .sort(field("semantic") * 0.6 + field("keyword") * 0.4, asc=False)
    .limit(10)
)
```

No second query. No merge step. No embedding call in your code, `semantic_similarity` embeds the query text server-side.

## The problem

Users type "iPhone 15 case blue". Keyword search nails the model number. Semantic search understands "blue protector". You need both.

Most stores make this hard:

- Chroma has no keyword search. The request ([#1330](https://github.com/chroma-core/chroma/issues/1330)) is its most-upvoted open issue, open since 2023.
- Elasticsearch fuses results with RRF, but RRF is a paid-tier feature. Free users get a license error.
- pgvector's README tells you to hand-roll `tsvector` plus RRF in SQL.
- Open WebUI rebuilt a BM25 index in Python on every query. A 10k-document collection took 30 to 60 seconds ([discussion #20737](https://github.com/open-webui/open-webui/discussions/20737)).

Even when hybrid works, two-index fusion is probabilistic. Each index returns its top 100, the app merges 200 candidates. A document ranked 101st in both lists never appears, even if it is the best overall.

## How TopK handles it

One index holds keywords and vectors. One scan produces the true top-k for your combined formula. Details in the [true hybrid search guide](/guides/true-hybrid-search).

Schema:

```python
from topk_sdk.schema import text, keyword_index, semantic_index

client.collections().create("products", schema={
    "name": text().required().index(keyword_index()),
    "description": text().index(semantic_index()),
})
```

Scoring is an expression, so you can add business signals:

```python
.sort(
    field("semantic") * 0.6
    + field("keyword") * 0.3
    + field("in_stock") * 0.1,
    asc=False,
)
```

Or require a keyword and rank by meaning:

```python
.filter(match("carbon") | match("renewable energy"))
.sort(field("semantic"), asc=False)
```

## Bring your own vectors

If you already have embeddings, swap `semantic_similarity` for `vector_distance` on an `f32_vector` field. Sparse vectors (SPLADE) work the same way with `f32_sparse_vector`.
