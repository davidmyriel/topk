## Short answer

One collection, a partition per user, a `timestamp` field, and a sort expression that mixes similarity with age.

```python
from topk_sdk.schema import text, timestamp, semantic_index
from topk_sdk.query import select, field, fn
import time

client.collections().create("memories", schema={
    "content": text().required().index(semantic_index()),
    "created_at": timestamp().required(),
})

user = "user-8841"
now_ms = int(time.time() * 1000)

client.collection("memories", user).upsert([
    {"_id": "m1", "content": "Prefers window seats on flights", "created_at": now_ms},
])

recalled = client.collection("memories", user).query(
    select(
        "content",
        relevance=fn.semantic_similarity("content", "book a flight"),
        age_days=field("created_at").elapsed(now_ms, "day"),
    )
    .sort(field("relevance") - field("age_days") * 0.01, asc=False)
    .limit(5)
)
```

No embedding call in your code. No cross-user leakage. Recency is part of the ranking, not a post-filter.

## The problem

- Memory tools store all users in one index and rely on a `user_id` filter. Users report bleed between agents and compliance concerns ([mem0 #3998](https://github.com/mem0ai/mem0/issues/3998), [openclaw #38417](https://github.com/openclaw/openclaw/issues/38417), [hermes-agent #34352](https://github.com/NousResearch/hermes-agent/issues/34352)).
- Recency scoring is done in application code. LangChain's `TimeWeightedVectorStoreRetriever` only works with in-memory stores. mem0 added "Memory Decay" as a feature because users kept asking.
- Write-then-read in the same turn fails on eventually consistent stores. See [why can't I find a document right after writing it](/answers/why-cant-i-find-a-document-right-after-writing-it).

## How TopK handles it

- **Isolation**: partitions are physically separate. Query one user, scan one user. Delete a user with one call. See [how do I keep each customer's data separate](/answers/how-do-i-isolate-data-per-customer).
- **Recency**: `timestamp` fields plus `elapsed()` and `date_part()` inside the query. Combine with `boost()` for hard cutoffs:

```python
.sort(
    field("relevance").boost(field("age_days") < 7, 1.5),
    asc=False,
)
```

- **Read-your-writes**: pass the LSN from the write to the next query.

```python
lsn = client.collection("memories", user).upsert([...])
client.collection("memories", user).query(..., lsn=lsn)
```

- **Keyword recall**: add `keyword_index()` to catch exact names, IDs, and rare terms that embeddings miss.
