## Short answer

Index code and notes into TopK with `keyword_index()`, `ngram_index()`, and `semantic_index()` on separate fields. Search with exact identifiers, regex, and meaning in one query. Keep one partition per repo or per developer. Nothing lives on the laptop.

```python
from topk_sdk.schema import text, int, keyword_index, ngram_index, semantic_index
from topk_sdk.query import select, field, fn, match

client.collections().create("code", schema={
    "path": text().required().index(ngram_index()),      # substring and regex on paths
    "chunk": text().required().index(keyword_index()),    # BM25 on identifiers and tokens
    "summary": text().index(semantic_index()),            # one-line description, embedded server-side
    "line": int().required(),
})

hits = client.collection("code", "repo-payments").query(
    select(
        "path", "line", "chunk",
        sem=fn.semantic_similarity("summary", "where do we retry failed webhooks"),
        kw=fn.bm25_score(),
    )
    .filter(match("webhook"))
    .filter(field("path").regexp_match(r"\.py$"))
    .sort(field("sem") * 0.7 + field("kw") * 0.3, asc=False)
    .limit(10)
)
```

## The problem

- Continue users report local index files of 30 to 50 GB ([#2917](https://github.com/continuedev/continue/issues/2917), [#4309](https://github.com/continuedev/continue/issues/4309)), extension-host crashes, and repos that never finish indexing. Both closed as not planned.
- Cursor's forum has at least eight "indexing stuck" threads. One reports 3 to 5 seconds per C++ file.
- Sourcegraph removed Cody's embeddings entirely, citing storage and update burden.
- Claude Code users have filed roughly ten duplicate requests for cross-session memory ([#34556](https://github.com/anthropics/claude-code/issues/34556), [#14227](https://github.com/anthropics/claude-code/issues/14227)). One built their own after "59 compactions".

Embedding a monorepo on a laptop, storing the vectors locally, and re-embedding on every change does not scale.

## How TopK handles it

- **Three index types in one query**. BM25 on code tokens and identifiers, ngram for `contains` and regex on paths, semantic on a short summary for intent. One index per field, all scored together.
- **Server-side embeddings**. No local model, no GPU, no re-embedding pipeline. Upsert text.
- **Partitions**. One per repo, branch, or developer. Delete a partition when a branch is gone.
- **Read-your-writes**. Index a file save and query it in the same command with an LSN.
- **Memory**. Same collection pattern as [agent memory](/answers/how-do-i-build-agent-memory-that-favors-recent-and-stays-private): timestamped notes, recency in the ranking.

## Limits

- 200 KB per document. Chunk files by function or by N lines.
- TopK does not parse code or compute symbols. Use tree-sitter or your own chunker, then upsert.
- One index per field. To get BM25 and semantic on the same text, store it in two fields or keep a separate summary field as above.
- No official plugin for Continue, Cursor, Cody, or Claude Code today. You would wire it through a custom context provider or an MCP server you write.
