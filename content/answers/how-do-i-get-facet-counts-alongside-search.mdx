---
title: "How do I get facet counts and aggregations alongside search results?"
description: "Count per brand, average price per category, or total matches for a filter, computed in the engine instead of your app."
---

## Short answer

Use `group_by` with aggregate functions. It runs over the full filtered set, not the page you returned.

```python
from topk_sdk.query import filter, group_by, field, agg, match

facets = client.collection("products").query(
    filter(match("wireless headphones"))
    .group_by(
        {"brand": field("brand")},
        {
            "count": agg.count(),
            "avg_price": agg.avg("price"),
            "min_price": agg.min("price"),
        },
    )
)
```

Same thing in SQL:

```sql
SELECT brand, COUNT(*) AS count, AVG(price) AS avg_price
FROM products
WHERE match('wireless headphones')
GROUP BY brand
HAVING COUNT(*) > 5
ORDER BY count DESC
LIMIT 20;
```

## The problem

- Milvus users have asked for aggregations since 2022 ([#19152](https://github.com/milvus-io/milvus/issues/19152)).
- Qdrant's approximate `count` under-reports by 20 to 60 percent ([#10125](https://github.com/qdrant/qdrant/issues/10125)). An exact count on 260 million points took 4.2 seconds ([#7274](https://github.com/qdrant/qdrant/issues/7274)). Facet correctness bugs are open ([#10589](https://github.com/qdrant/qdrant/issues/10589)).
- Chroma has no sorting or aggregation ([#469](https://github.com/chroma-core/chroma/issues/469), open since 2023).
- Elasticsearch `terms` on high-cardinality fields trips the circuit breaker ([#86531](https://github.com/elastic/elasticsearch/issues/86531), open since 2022).

The workaround everywhere is to fetch thousands of rows and count in the app.

## How TopK handles it

Aggregation is a query stage. Filters, keyword matches, and vector scores can all feed it.

Available in Python, JavaScript, and SQL: `count()`, `count(field)`, `sum`, `min`, `max`, `avg`.

Group by a computed key:

```python
group_by(
    {"price_band": field("price") < 50},
    {"count": agg.count()},
)
```

Multiple keys:

```python
group_by(
    {"brand": field("brand"), "in_stock": field("stock") > 0},
    {"count": agg.count(), "avg_rating": agg.avg("rating")},
)
```

Run the facet query and the results query in parallel. They read the same index.

## Limits

- Group-by returns aggregates only, not top-N documents per group.
- `SELECT *` is not allowed in SQL group-by queries. Every column must be a key or an aggregate.
- Exact `count()` without grouping is a separate `count` stage in SQL (`SELECT COUNT(*)`).
